## What this is

**Inte-Run — "The Intelligent Training Companion"**: an evidence-based running-coach app. A goal + current
fitness becomes a periodised plan; live GPS runs with spoken coaching; a logbook and progress; strength
training; Inte-Club (a social profile). It ships as a PWA on GitHub Pages **and** a native iPhone + Apple Watch
app. The owner (Adam, UK) runs it on an iPhone 16 Pro Max on the iOS 27 beta and an Apple Watch Ultra.

⚠️ **The name is `Inte-Run` ("intelligent run"). Rename DISPLAY text only, never identifiers:**
- `interun_*` localStorage keys hold every logged run, the profile and the plan; backups find keys by that
  prefix. Renaming them orphans the runner's whole history.
- `interun://app` is the web view's origin, which localStorage is filed under. Same consequence.
- `com.interun.app`, `InteRunApp` / `InteRunWatchApp` / `InteRunWidgetBundle`, the `ios/InteRun*` paths and the
  `"InteRunSelfCheck"` key are identifiers. The visible name is `CFBundleDisplayName` in both Info.plists.
- The repo and Pages URL stay `Inte-Run`. Never describe the name as spoken "inter-run".

## Architecture

- **`src/`** — the pure-TypeScript engine, no runtime dependencies, unit-tested. `web/entry.ts` re-exports it
  and esbuild bundles it into the browser global **`RC`**. ⚠️ Bundled exports are getters, so assigning
  `RC.x = …` in a probe silently does nothing.
- **The whole app is ONE file, `web/app.html`, generated by `web/app.ts`** — a giant template literal holding
  the HTML, one `<style>` block and all the runtime JS. **Never hand-edit `web/app.html`.** The build also
  writes `docs/` (`index.html`, `manifest.webmanifest`, `sw.js`) and mirrors `web/voices/` → `docs/voices/`.
- **`docs/roadmap/index.html`** — the owner's Road Map. Hand-written; edit it directly.
- **`ios/`** — the native app: a Swift shell running `docs/` in a WKWebView over `interun://app`, the watchOS
  app, a widget extension (Live Activities) and a UI-test target. The Xcode project is generated by
  `python3 ios/make-project.py`, and regenerating overwrites it.
- **`alfie-proxy/`** — the one Cloudflare Worker: Ask Alfie's online answers (`POST /`) and Strava
  (`/strava/*`). Deployed by hand; `npx tsc --noEmit` does not cover it (see `alfie-proxy/README.md`).
- ⚠️ **`docs/` is one page serving two platforms** (the PWA and the native app); a change made for one lands on
  the other.
- ⚠️ **The native app updates its web layer over the air**: it downloads a newer `docs/index.html` from Pages
  and adopts it on the next launch (`WebUpdateService.swift`). A web-only change pushed to `main` reaches the
  owner's phone without Xcode; voices, icons, other pages and all Swift still need a rebuild. A page that needs
  something new from the native side must check a capability flag that side sets (for example
  `window.__interunCoachNativePlay`) — never whether a message handler exists.
- Plans and specs: `PLAN.md` (the plan to beat Runna: strength, launch hygiene, parity), `YOUTH.md` (the 12–17
  programme), `DPIA.md`, `APPSTORE.md`, `DESIGN.md` (the design brief), `WATCH-REDESIGN.md`.

## CRITICAL — runtime JS inside `web/app.ts`

The runtime JS sits inside the outer template literal, so:
- **No backticks anywhere in runtime JS — including JS and CSS comments.** One closes the literal. Symptoms:
  `Expected a semicolon`, `Identifier cannot follow number`, or a `ReferenceError` naming a runtime variable at
  BUILD time. Check before building: `git diff web/app.ts | grep '^+' | grep -F '`'`.
- Double every backslash in runtime regexes and strings: `\\d`, `\\s`, `\\/`, `\\n`, `\\uXXXX`. A single one is
  eaten silently, and the regex then matches something else.
- Quotes inside runtime strings as `\\"`, not `\"`; prefer single-quoted runtime strings around HTML. A
  typographic apostrophe (’) needs no escaping.
- No literal `${...}` inside runtime strings.
- ⚠️ **`node web/app.ts` does not syntax-check the emitted JS, and a failed build leaves the OLD `web/app.html`
  in place**, so every check after it passes against the previous build. Read the build's own exit code, not
  `tail`'s. `npm run verify` runs `node --check` on every emitted `<script>` block.
- Silent runtime traps that keep recurring: a `const` read before its declaration throws inside a `try/catch`
  and nothing happens (store keys are declared together near the top for this reason); two top-level
  functions with one name — the later one wins silently; `el()` takes an HTML string, not a tag name;
  `isoAdd()` returns a Date, not a string.

## Commands

```bash
npm run verify         # the whole recipe in one command — quote its one summary line, never a memory
npm run verify:quick   # UTC only, no audits (~2 min): the development loop
node web/app.ts        # build web/app.html + docs/ (after ANY edit to web/app.ts)
npx tsc --noEmit       # one pinned pre-existing error, in test/onboarding-wizard.test.ts
node --test            # the suite (about 1,800 tests)
```

- `npm run verify` = build (exit code read) → `docs/voices/` clean → `node --check` on every emitted block →
  tsc (one pinned error) → `node --test` under UTC, `Pacific/Kiritimati` and `Pacific/Pago_Pago` (they
  disagree about the date) → the two engine audits. `VERIFY_CONCURRENCY=N` runs fewer test files at once
  when the Mac is bogged down (the share-export gate times out under heavy swap).
- `test/share-export-bytes.test.ts` needs headless Chrome (found automatically on macOS, or set
  `CHROME_PATH`). Without it those tests fail on purpose.
- ⚠️ **`node web/app.ts` can silently wreck the committed coach audio**: it mirrors the gitignored `web/voices/`
  over the committed `docs/voices/`. After building, check `git status --short docs/voices/` and restore with
  `git checkout -- docs/voices/` unless you deliberately regenerated audio (`notes/voice-coach.md`).
- zsh does not word-split `node --test $FILES` — use an array. node prints failures as `ℹ fail N`.

## Keep sessions light

- **`web/app.ts` is 41,000 lines / 2.8 MB.** Never `Read` or `cat` it whole: `grep -n` for the symbol, then
  read a range (`sed -n 'A,Bp' web/app.ts`).
- ⚠️ **Never `grep` or `cat` `web/app.html` or `docs/index.html` without limiting the output.** They are 14 MB
  with multi-megabyte single lines (inlined images, the minified engine), so one match can flood the context.
  Use `grep -c`, `grep -o '.\{0,80\}NEEDLE.\{0,80\}'`, or search `web/app.ts` instead.
- Don't `grep -r` from the repo root: it also walks `node_modules/`, two stale full copies of the repo in
  `.claude/worktrees/`, and the 14 MB build outputs. Scope searches to `src/ web/app.ts test/ ios/ tools/ notes/`.
- Pipe long output through `tail`/`head`; prefer `npm run verify`'s one-line summary to raw test output.
- Hand broad sweeps (many files, whole-app audits) to a subagent and keep only its conclusion.
- One stage per session: start a fresh session for the next big feature rather than carrying one across several.

## Rules that each cost a real bug

- **Never assign `PLAN` from an `applyProfile()` result by hand — call `adoptPlan(out)`** (it snaps weeks to
  Mondays and resyncs iOS reminders and the watch). `applyProfile` is pure; `adoptPlan` and `recompute` commit.
- **`PLAN.weeks` is a display summary with no steps, exercises or pace bands; the prescription is
  `RAW.weeks`** (`rawSessionsForIso()`). Reading the wrong one fails silently.
- **A session id names its calendar week** (`2026-10-12-d1-threshold`, `RC.sessionIdFor`). The plan is rebuilt from
  today, so a block loses a week every Monday: anything keyed on a week NUMBER slips a week. A store keyed on a session
  id reads old `w3-d1-…` ids through `legacySid` (notes/manage-plan.md, B4).
- **Dates are UTC** (`todayIso()`, `isoAdd()`). Never build an ISO date from a Date changed with local setters;
  `new Date(iso + "T00:00:00")` has no Z.
- Code that measures or scrolls a rendered screen goes in `wire()`, not `buildNav()` (which runs once at boot,
  before any screen exists). Never measure inside a bottom sheet before adding `.on`.
- Don't re-render on every keystroke (it rebuilds the field under the finger). A DOM kept for a transition has
  duplicate ids, so `$()` finds the wrong node.
- An undeclared `var(--x)` voids the whole CSS declaration silently. Theme tokens are declared in FOUR places
  (`:root`, the prefers-color-scheme block, both `data-theme` blocks). Translate design tokens by value, never
  by name. Measure contrast from rendered pixels, in light mode as well as dark.
- The app's bottom sheet is z-index 70; full-screen overlays above it (share studio 92, club viewer 96) need
  their own sheet, or a question opens behind them.
- Focusable text is at least 16px (iOS zooms, and pinch is disabled). Hit areas are at least 44px — grow them
  with `::after`, not the box.
- A flex item defaults to `min-width: auto` and won't shrink; `overflow-y: auto` alone also makes a box
  horizontally scrollable (add `overflow-x: clip`).
- No external network assets in the app: everything is inlined, and audio comes from `docs/voices/`.
- Every `$("id")` must resolve to a rendered id and every rendered button must be wired (both guarded). "Looks
  live, does nothing" is this project's most repeated defect.
- Never fabricate data — no invented distance, route, time or heart rate. Absent is absent, never 0.

## How this project tests

- **Re-break a guard before believing it:** put the bug back and watch the test fail. **Copy the file aside
  first and copy it back — never `git checkout` a file to undo a re-break** (it has destroyed uncommitted work
  twice). A re-break whose anchor isn't unique tests nothing.
- Guard the invariant, not the implementation. Derive collections rather than hand-listing them. A test that a
  thing works is not a test that anything uses it — add a reachability check.
- Lift the real function and its real constants out of the built page; a probe that supplies its own
  dependency measures an easier program. A fixture must carry the longest real value, not a tidy one.
- Strip comments before sweeping source (comments quote the strings guards forbid), and anchor a block-comment
  stripper to the start of a line (`accept="image/*"` opens a fake one). Brace-match a function body — a
  character window is not a function.
- Re-measure after the LAST edit before quoting a number.

- ⚠️ **Use Xcode-beta for anything that reaches his phone** — it runs the iOS 27 beta, which only Xcode 27 beta

- Run `node web/app.ts` first (`docs/` is embedded at build time). Signing needs `ios/team.txt` (gitignored);

- Install: a Release build for `platform=iOS,id=9AC09027-7780-558A-824A-2C535D8203D2`, then
  `xcrun devicectl device install app …`. The phone must be awake, unlocked and on the same Wi-Fi.
- Never pass `-sdk` to xcodebuild for this project; use `-destination`. `ENABLE_DEBUG_DYLIB = NO` on the watch
  target is load-bearing.
- TestFlight: `xcodebuild -exportArchive` with `destination upload` uploads through Xcode's signed-in account
  (no API key needed); adding testers needs an App Store Connect key.
- The Worker: `npx wrangler login` in the owner's terminal (he must click Allow within about two minutes), then
  deploy from `alfie-proxy/`.

## Testing in a browser

- Build, then serve `docs/` over HTTP (`python3 -m http.server <port> --directory docs`; `file://` blocks
  fetch). **Check the port is free first** (`lsof -nP -iTCP:$PORT -sTCP:LISTEN`) and prove the right build is
  being served (`curl -s localhost:$PORT/index.html | grep -c <a symbol you just added>`) — leftover servers
  silently serve old builds. The page registers a service worker: clear it and cache-bust (`?v=N`) on reload.
- Seed a profile through `localStorage rc_profile_v1`; get past the welcome by clicking `#welcomeback` (it also
  leaves by itself after 4 s).
- Headless Chrome: size the window with `Browser.setWindowBounds` — an unsized window can be 1px tall, and every
  layout reading is then noise. Check whether an overlay is on top before trusting an `elementFromPoint` test.
